## 4. 이미 작업 중인 저장소에 적용하기

`walk-music-add-1109.zip`을 저장소 맨 위에 넣고 아래 프롬프트를 붙여 넣으면 Claude Code가 기존 파일을 덮어쓰지 않게 푼다. 들어 있는 것은 모두 새 경로다. 탐색기·Finder에서 직접 풀어 docs/·data/ 폴더를 끌어다 놓으면 같은 이름의 폴더를 통째로 바꿀 수 있으니 그렇게 하지 않는다.

```
docs/CHANGES_1109.md                     이 파일
docs/HANDCALC.md                         손계산 노트
docs/updates/walkmusic_v1_to_v3.patch    11/8 수정판도 아직 반영하지 않은 저장소용(SPEC v0.1). 11/8 + 11/9
docs/updates/walkmusic_v2_to_v3.patch    11/8 수정판을 반영한 저장소용(SPEC v0.2). 11/9만
data/video_checks.csv
data/video_markers.csv
data/debrief.csv
```

패치는 스타터 키트 원문을 기준으로 만들었고 git blob 번호가 들어 있다. `git apply --3way`를 쓰면 Claude Code가 고친 곳과 겹치지 않는 부분은 그대로 합쳐지고 겹치는 곳에만 충돌 표시가 남는다. 키트 원문(v0.1, v0.2)에 시험 적용했을 때 둘 다 충돌 없이 v0.3 키트 문서와 같아졌다. DECISIONS·DATA_FACTS·params.toml을 Claude Code가 고친 저장소를 흉내 내 시험했을 때는 그 세 파일의 겹치는 줄에서만 충돌이 났다.

Claude Code에 아래를 붙여 넣는다.

```text

0. zip을 저장소 맨 위에 풀되 기존 파일은 하나도 덮어쓰지 마(unzip -n, unzip이 없으면 같은 동작의 python). docs/CHANGES_1109.md, docs/HANDCALC.md, docs/updates/ 패치 2개, data/video_checks.csv·video_markers.csv·debrief.csv가 생긴다. 이미 있는 파일이라 건너뛴 것이 있으면 알려 줘.
```
