# DATA_FACTS — 실제 파일에서 확인한 사실

Phase 0에서 시범 측정 zip을 열어 채운다. '문서로 아는 것'은 Sensor Logger 공식 문서에서 확인한 내용이고, '파일에서 확인한 값'이 비어 있으면 아직 확인하지 않은 것이다. 추측해서 채우지 않는다. SPEC과 다른 점은 DECISIONS.md에 적는다.

## 규칙

- 좌표 값, 기기 이름 등 개인을 알아볼 수 있는 값은 적지 않는다. 거리, 속도, 정확도, 시각만 적는다.
- 값마다 어떻게 확인했는지(어떤 계산인지)를 '메모'에 한 줄 적는다.
- 시범 파일 1개로 확인한 것은 '시범 1개 기준'이라고 적고, 실제 회차가 들어오면 다시 확인한다.
- 센서마다 파일이 따로이므로, 아래 표의 센서 이름은 파일 이름과 같게 쓴다.

**확인 범위.** §0–§9는 **시범 1개 기준**이다: `TEST_A_1107`(iOS 26.2.1, Sensor Logger 1.68.1, standardisation=false, 바지 앞주머니). §10은 11/8 사전 점검 3개(A, 같은 폰, 허리 파우치) 기준이다. 실제 회차나 Android 기록이 들어오면 다시 확인한다. 계산은 저장소 밖 일회용 스크립트(numpy·pandas·scipy)로 했고, Phase 1의 `inspect`·`qa`가 같은 값을 다시 내야 한다. t_s는 Metadata `recording epoch time`부터 잰 초다.

## 9. SPEC에 필요한 변경

- 기록 시작의 대안 '모든 센서 첫 `time`의 최솟값'(SPEC §5.1)은 Location의 기록 전 점(t_s −14.2 s)을 고른다. 기준은 `recording epoch time`, 대안은 IMU 파일만 — D-43 (D-20)
