# 실험 2 영상 판독 도구 (DECISIONS D-83)

메인 카메라 영상(60 fps)에서 30 m 통과 시간, 걸음 수, 걷기/뛰기 판정용 사진을 낸다. 패키지(`src/walkmusic`) 밖의 도구이고 ffmpeg, numpy, scipy, matplotlib, Pillow가 필요하다. 영상(`data/raw/data-vid/`)은 저장소에 없다.

```
python -I tools/video/read_exp2_video.py "data/raw/data-vid/IMG_5479.MOV" <출력 폴더> [--tiles]   # 영상 하나(약 100 s)
python -I tools/video/collect_readings.py <출력 폴더> 0.94                                         # 시행 표 → <출력 폴더>/collected.csv
python -I tools/video/apply_readings.py <출력 폴더>/collected.csv                                  # 기록지와 data/video_exp2.csv에 넣기
python -I tools/video/gait_tiles.py <출력 폴더> <그림 폴더>                                         # 걷기/뛰기 판정용 사진
python -I tools/video/sensitivity.py <출력 폴더> <임시 폴더> 0.92 0.96                              # k를 바꾼 가설 3 판정
```

## 읽는 방법

1. **배경:** 카메라가 가만히 있던 가장 긴 구간(가로 어긋남 ±4 px 안)의 프레임 중앙값.
2. **기준선:** 배경에서 붉은 트랙 면의 바깥 가장자리 줄을 찾고(`vgeom.red_edge`), 그 줄 위의 밝은 물체 가운데 화면 간격이 1411 ± 15 px인 쌍을 5 m·35 m 물병으로 본다(`vgeom.find_bottles2`).
3. **발 띠:** 가장자리 줄 위 8 px ~ 아래 16 px를 줄을 따라 편다. 프레임마다 배경과 가장 잘 맞는 정수 어긋남(±8 px)을 찾아 맞추고(오차가 8% 넘게 줄 때만), 색마다 밝기 중앙값을 뺀다.
4. **신호:** 밝아짐(흰 신발, 문턱 25/14)과 변화(어느 신발이나, 문턱 80/40, x로 27 px 열기 연산을 빼서 몸 그림자를 없앰). 열마다 2 s 토막의 아래 25%를 바탕으로 뺀다.
5. **디딤:** 같은 x에 0.10 s(다시 0.30 × 걸음 간격) 이상 머문 덩어리. 같은 속도로 한쪽으로 가는 줄을 셋까지 찾아 가장 고른 것을 고른다. 시간과 거리가 모두 같은 배수(2–6)인 틈은 그만큼 채우고 표시한다.
6. **화면상 통과 시각:** 디딤 시작점 (t, x)을 이은 꺾은선이 물병 x를 지나는 시각.
7. **시차 보정:** t30 = 화면상 시간 ÷ k, k = 1 − d ÷ D. 걸음 수는 화면상 구간을 양쪽으로 Δt × (1 − k) ÷ k의 절반씩 넓힌 구간 안의 디딤 수다.
8. **걷기/뛰기:** 구간 가운데 6걸음의 디딤 시작 프레임 사진에서 뒷발이 땅에 있으면 걷기, 이미 떠 있으면 뛰기. 사람이 사진을 보고 정한다(`apply_readings.py`의 `GAIT`).

## 한계

- 발 띠의 디딤 덩어리는 실제 접촉보다 조금 길게 잡힌다(걷기 쪽으로 약 0.05–0.1 s). 그래서 디딤 겹침만으로 걷기/뛰기를 가르지 않는다.
- 빠른 시행(165% 이상)은 걸음 수가 ±1–2 불확실할 수 있다. 통과 시간은 판을 바꿔도 1% 안에서 같았다.
- 걷는 줄과 물병 줄의 간격 d는 시행마다 재지 못했다(신발 아래쪽과 트랙의 대비가 낮다). 2026-11-21 자료는 모든 시행에 d = 0.9 m, D = 15 m를 썼다.

# 점프·진자 영상 판독 도구 (DECISIONS D-84)

점프 영상(240 fps)에서 체공 시간, 진자 영상(60 fps)에서 10번 흔들림 시간과 굽힌 무릎 각을 낸다. 값은 `data/video_checks.csv`(`jump_flight`, `swing_10`)와 `data/video_markers.csv`(`pendulum_bent`)에 들어간다.

```
python -I tools/video/vframes.py <영상> <출력 jpg> --t0 12.0 --t1 12.3 [--crop x y w h] [--scale 0.5]    # 프레임을 번호·시각과 함께 한 장에(눈으로 대조)
python -I tools/video/jump_read.py "data/raw/data-vid/B-JUMP.MOV" <출력 폴더> --crop 300 1200 500 440 [--plot]   # 체공(발 둘레 화면을 --crop으로 준다)
python -I tools/video/marker_track.py "data/raw/data-vid/A-90-1.MOV" <출력 폴더> [--sheet T0 T1]          # 테이프 추적(영상 하나에 약 5분)
python -I tools/video/swing_read.py <출력 폴더> A-STRAIGHT-1 A-90-1 ... [--plot]                          # 10번 흔들림 시간
python -I tools/video/knee_read.py <출력 폴더> A-90-1 A-90-3 ... [--ratio 0.25] [--plot]                  # 굽힌 무릎 각과 기록지 줄
python -I tools/video/apply_pendulum_jump.py <출력 폴더>                                                   # 두 기록지에 넣기
```

## 읽는 방법

1. **점프 체공:** 프레임마다 신발 아래 끝(바닥보다 밝은 화소가 있는 가장 아래 줄)의 높이를 찾는다. 실내 조명이 프레임마다 깜빡여(밝기 약 1.3배 차이) 밝기 문턱을 프레임마다 다시 잡는다. 이륙과 착지 시각은 그 높이에 이어진 두 직선을 맞춘 꺾이는 점이다. 프레임 간격이 고르지 않아 프레임 수가 아니라 프레임 시각의 차를 쓴다.
2. **테이프 추적:** 색 조건으로 노랑·파랑·빨강 덩어리를 찾는다. 가만히 있는 덩어리(20프레임 앞뒤 모두에 25 px 안의 덩어리가 있는 것)는 배경이라 뺀다. 노랑은 앞 프레임에서 가장 가까운 덩어리, 파랑은 노랑과의 거리가 영상 내내 거의 같은 덩어리다.
3. **10번 흔들림:** 노랑 테이프가 가장 크게 움직이는 방향으로 잰 위치의 같은 쪽 끝점 사이 시간. 이어진 흔들림의 두 번째 끝점에서 열두 번째 끝점까지다(끝점이 11개뿐이면 첫 번째부터, 11개가 안 되면 내지 않는다). 양쪽 끝점으로 따로 잰 값의 평균을 쓴다.
4. **굽힌 무릎 각:** 정강이 축은 노랑 → 파랑이다. 파란 테이프가 관절선 아래에 있어 무릎 점은 파랑에서 정강이 축으로 (노랑–파랑 거리 × 0.25) 올린 점으로 둔다. 엉덩관절 점은 빨간 테이프에서 (노랑–파랑 거리 × 0.28) 내린 높이에, 좌우는 그 높이에 중심을 둔 원이 무릎 점의 호에 가장 잘 맞는 곳이다(빨간 테이프가 허리띠 높이에 있다). 기록지에는 추적이 길게 빠지지 않은 주기마다 같은 간격으로 6프레임을 넣는다.

## 한계

- 점프는 카메라 쪽 발만 본다. 꺾이는 점은 문턱을 바꿔도 0.005 s 안에서 같았다.
- 착지 뒤 발이 눌리며 신발 아래 끝이 계속 내려가면(A-JUMP의 두 번째 점프: 20프레임에 12 px) 착지 창이 꺾이는 점을 벗어나 맞춤이 실패한다. 출력의 '착지 앞 기울기'가 다른 점프(1000 px/s 이상)보다 훨씬 작으면 그 값은 쓰지 않는다(DATA_FACTS §20).
- 바닥의 조명 반사가 신발 아래에 들어오면 그것을 신발로 잡는다. 자르는 화면에서 뺀다.
- 센서가 센 점프와 영상의 점프 번호가 다르면 `<영상 이름>_pairing.json`(`pairs`: 영상 번호 → 센서 번호, `unread`: 값을 넣지 않을 영상 번호, `note`)을 출력 폴더에 두면 `apply_pendulum_jump.py`가 그 번호로 적는다(D-87).
- 무릎 올림 비율과 엉덩관절 점은 영상에서 정한 추정이다. 올림 0.15–0.35, 내림 0–0.5로 바꾸면 평균 각이 ±2.4° 안에서 달라진다. 읽은 각의 불확실성은 약 ±5°로 본다(DATA_FACTS §19).
- 빠르게 움직이는 구간은 테이프가 번져 추적이 빠진다. 평균은 빠진 구간을 시간으로 이어 붙여 낸다.
